# V0.6 · 气泡式 AI 助手与全量 UI 地图适配

| 项 | 内容 |
|---|---|
| 版本号 | V0.6（V0.6.1） |
| 发布日期 | 2026-10-17 |
| 版本性质 | 人机交互范式重构（常驻右侧抽屉 → 场景化气泡助手） |
| 小版本数 | 1 次主线会话 |
| 当前状态 | **当前最新版**（私有完整版） |

> 本文记录私有完整版的建设过程，文中点名的业务文件与接口均属私有代码库；本公开仓库仅含服务骨架、部署配置与演进档案。

## 一、版本定位

经过 V0.3~V0.5 的信息架构重构与模块扩张，工作台的页面、卡片、框架、入口位置均已大幅变化，旧 AI 助手仍按旧 DOM 结构工作——不知道新页面有什么、点不到新控件、回答失去准头。V0.6 从两个维度重建 AI 助手：

1. **认知层**：建立覆盖全站页面、功能、控件的唯一真源 UI 地图，前端引导与后端对话共用同一份；
2. **交互层**：移除常驻右侧聊天抽屉，改为**低打扰气泡小窗**——按用户所在场景主动预测意图，确认后直接高亮目标，不确认则引导描述。

## 二、需求定义（专业转写）

| # | 要求 | 落地形态 |
|---|---|---|
| 1 | 全站页面、功能、点击全部覆盖且流畅 | 唯一真源 UI 地图，逐页登记功能区与可操作控件 |
| 2 | 预测用户操作 | 场景切换时气泡主动询问（如进入天气页："是不是在找某功能？"），确认→执行高亮引导；否认→输入框让用户描述要找什么 |
| 3 | 形态改气泡 | 右侧抽屉完全移除，AI 以小窗气泡形态存在，仅在合适界面弹出 |
| 4 | 场景短说明 | 用户进入某功能区时，以极简几个字说明该区域用途，不连续打扰 |
| 5 | 文案风格 | 一针见血，不啰嗦 |
| 6 | 质量要求 | 视觉验证 + 服务器后台代码验证双通过后上线 |

## 三、架构设计

### 3.1 唯一真源 UI 地图（wb-map）

此前"前端知道的页面结构"与"后端 AI 提示词里的 UI_MAP"是两份各改各的清单，页面一重构就双双过期。V0.6 的核心架构动作是**合并为单一真源**：

```
public/wb-map.js（唯一真源：页面 / 功能区 / 控件 / 引导语）
        ├─ 前端 ai-buddy：场景检测、气泡预测、高亮引导
        └─ 后端 ai.js：UI_MAP 由同一份地图生成，对话时引用
```

任一处新增/移动页面或控件，只需改地图一处，前后端同时更新，从机制上杜绝"AI 说的和页面长的对不上"。

### 3.2 气泡助手（ai-buddy）

| 能力 | 说明 |
|---|---|
| 场景感知 | 监听页面/标签切换，结合 UI 地图判定用户当前所在功能区 |
| 意图预测 | 进入典型场景时弹出气泡，给出一个高概率目标建议（"是不是在找 X？"） |
| 一键引导 | 用户确认后，目标元素执行高亮动画定位，代替翻找 |
| 兜底检索 | 否认建议时，气泡提供输入，按描述在 UI 地图中检索并引导 |
| 功能短说明 | 首次进入功能区给一行极简说明，频控限制，不重复打扰 |
| 聊天保留 | 需要深度问答/派发任务时仍可展开对话，但不再常驻占据右栏 |

### 3.3 文件变更

| 文件 | 角色 |
|---|---|
| `public/wb-map.js` | 新增，全站 UI 地图唯一真源 |
| `public/ai-buddy.js` / `ai-buddy.css` | 新增，气泡助手逻辑与样式 |
| `public/index.html` | 移除抽屉挂载，接入小窗与地图 |
| 后端 AI 模块 | `UI_MAP` 改为由真源地图生成，对话上下文随地图自动更新 |

## 四、关键决策

| 决策 | 理由 |
|---|---|
| 抽屉改气泡而非"抽屉可收起" | 常驻抽屉在信息密度已很高的新工作台中持续挤占空间；场景化建议比开放聊天框更符合"助手"定位 |
| 主动提示必须有频控与一键关闭 | 主动气泡的最大风险是打扰，短文案 + 低频次 + 不打断操作是硬约束 |
| 地图不直接写后端、由真源生成 | 前后端两份结构清单是历次 AI 失准的根因，单一真源从机制上解决 |
| 高亮引导优先于口头描述 | 用户找功能时，一次元素高亮胜过四句文字指引 |

## 五、部署与验证

| 环节 | 做法 |
|---|---|
| 上线前备份 | 线上文件打包备份（`_bak_buddy_20261017.tgz`，留存 md5 指纹） |
| 灰度方式 | 上传 6 个变更文件，逐一 md5 指纹核对一致后重启服务 |
| 后台验证 | 服务重启后健康检查 + 后端直接实跑 UI 地图生成，确认对话侧拿到的结构与前端同源 |
| 视觉验证 | 浏览器实测各页面切换时的气泡时机、高亮定位、否认兜底与展开聊天 |
| 回归边界 | 抽屉移除后，原有聊天请求、任务派发、动作执行链路保持可用 |

## 六、V0.5 → V0.6 总览对比

| 维度 | V0.5 | V0.6 |
|---|---|---|
| AI 入口形态 | 常驻右侧抽屉 | 场景化气泡小窗 |
| 主动性 | 用户提问才响应 | 按场景预测意图、主动短提示 |
| 找功能方式 | 文字问答 | 一键高亮定位 + 描述检索兜底 |
| UI 结构来源 | 前后端两份清单，易过期 | wb-map 单一真源，前后端同源生成 |
| 空间占用 | 固定一整条右栏 | 仅一个气泡，按需展开 |
| 对新页面的覆盖 | 靠手工补登记 | 随地图统一登记、统一生效 |

## 七、截至 V0.6 的系统全貌

| 层 | 组成 |
|---|---|
| 前端（浏览器） | 总览仪表盘、学习通（课程/作业/待办/签到含相机卡）、教务、天气（实况/逐小时/地图/月度/趋势）、记账、情报分析、AI 气泡助手；流场背景与昼夜皮肤；电脑/手机双端适配 |
| 云端（server2） | Node 零第三方依赖服务：学习通客户端与 Agent 长效操作引擎、AI 双模型路由、会话/存储/实时画面、天气聚合与瓦片代理、相机同源代理、访问口令闸门 |
| 本地（用户电脑） | 教务 + 天气网关：校园网出网抓取、验证码识别、主备租约、天气 JSON/瓦片缓存回传 |
| 外部智能服务 | 前端轻量推理模型（聊天/识图/分析）、后端旗舰模型（长效 Agent） |

## 八、版本边界与后续方向

- 气泡的预测质量依赖 UI 地图的持续维护；新增页面若未登记地图，助手将不知道该区域——地图已做成单文件最简维护形态；
- 主动提示的频控参数（每功能区首次、单日上限）按保守值设定，后续可按使用感受调整；
- 业务代码属私有完整版，本公开仓库只提供服务骨架与演进档案；历史各版本的业务代码均未公开发布，版本记录以 `docs/releases/` 文字档案为准。
