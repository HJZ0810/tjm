## 三、V0.4.1 · 微信账单 Excel 美化

### 3.1 数据实况

| 维度 | 实况 |
|---|---|
| 文件 | 桌面 `账本.xlsx`，微信支付账单导出 |
| 体量 | 511 笔收支，2026-07-13 ~ 2026-10-13 |
| 结构 | 前 17 行为平台说明区，第 15 行起才是表头与明细，11 列，无任何格式 |

### 3.2 一次方向性返工

第一版按"看板思维"重构为汇总图表册，原始明细被弱化；用户明确要求**原数据一行不少、只优化观感**。随即推倒重做，确立两条不可妥协的原则：

1. 主表 529×11 格**逐格比对零差异**（说明头、列序、明细顺序、斜杠占位符原样保留），版式层与数据层严格分离；
2. 汇总与图表全部使用**整列引用公式**驱动——删行、改金额、改商户名后自动重算，不允许把数字硬编码进图表。

另处理商户名空格变体（同一商户多种写法）的归并口径，保证公式归并与缓存值一致。**交付物为另存的美化副本，原文件不动。**

## 四、V0.4.2 · 账本网页仪表板

将账单数据以网页仪表板形式并入工作台（`#ledger`）：8 张图表卡 + 50 行明细表 + 5 张统计卡，经云端口令闸门后渲染，手机与电脑均可访问。

| 项 | 说明 |

| 顺手修复 | 纵轴出现 ¥8,000 / ¥5,333 / ¥2,667 类"丑数"刻度，重写 niceScale 刻度算法取整 |

### 4.3 同步完成的下阶段需求编排

本会话后半段为后续建设编排了正式任务书，关键决策包括：界面删除运维向技术文案（心跳/本机身份等）；总览改图标跳转卡与概要计数；实时画面并入学习通页 Tab；双皮肤（昼/夜）背景随时间与天气变化；情报分析系统按**独立产线**建设。

## 五、V0.4.3 · 情报分析 + 全站背景 + MSN 天气（跨夜大会话）

### 5.1 情报分析系统：独立产线六红线

情报分析系统脱胎于服务器上既有的聊天分析产品，但按明确的架构边界**复制一份副本后改造**，与原产品完全隔离：

1. 原产品目录、域名、服务、环境文件一律不动；
2. 禁止在原目录原地修改，开工前 md5 留证、收工字节级比对；
3. 不共用库/存储/日志/端口/环境变量，不互相 import、不互调接口；
4. 不用 iframe 嵌套旧站，旧站不挂新系统入口；
5. 新系统代码与文案中不出现旧产品命名；
6. 新系统独立部署于工作台体系。

### 5.2 情报分析的产品化修正

| 维度 | 修正内容 |
|---|---|
| 任务可靠性 | 完整分析耗时很长，历史记录改为**本地持久化**（支持删除），任务不依赖云端会话存活，刷新/返回后点击历史即可加载，避免"等半天回来全没了" |
| 结果呈现（移动端） | 截图识别与分析结果改为页内内联展示，不再用弹窗；不用滑到页面底部才能看到状态 |
| 信息确认 | 识别确认环节补齐对方昵称、对方头像、我方头像 |
| 关系选项 | 去除情感向标签，定位为商务/同学/师生等日常聊天分析；选项定为「刚认识 / 认识中 / 很熟悉 / 不喜欢」四档，默认刚认识 |
| 布局 | 独立整页改为**左右分栏**（左：情报列表与筛选；右：详情与分析对话），与 AI 对话页交互范式对齐 |
| 消息详情 | 点击单条消息的详情在移动端就近展示，不再要求滚动到页面最底部 |

### 5.3 模型分层提速

完整分析过慢，经协议实测后确定模型分工：

| 通道 | 模型 | 协议/特性 |
|---|---|---|
| 前端 AI 聊天 + 情报分析 | DeepSeek 推理模型 Flash 版 | 1M 上下文、支持图片输入（识图可用）、Chat 与 Responses 协议均可用；分析任务开启思考模式，小型 UI 操作类请求不开思考以提速 |
| 后端长效 Agent | 保持原有阶跃星辰模型不变 | 长任务对首字延迟不敏感，重质量不重速度 |

### 5.4 DeepSeek 流场背景全站化

- 背景从口令页独占推广到全站：以爬取镜像中的点阵流场源码为像素基准（Canvas 2D、spacing≈90、基色 rgb(60,100,160)、鼠标跟随）；
- 封装为独立背景组件，不遮挡正文、不拦截点击，中低端机与 `prefers-reduced-motion` 下降级为静止；
- 从爬取的多套背景样式中按页面分配（总览/学习通/天气等各一套），并提供昼/夜自动切换与设置内**手动切换**入口；
- 修正浅色模式下高饱和纯绿、大红大紫的配色事故，统一为克制配色。

### 5.5 MSN 天气复刻与三层数据链路

**复刻基准**：本地离线镜像（26 页可点可缩放）作为像素验收标准答案，前端不直连 MSN、不持有任何上游密钥。

**数据链路（本版定型）：**

```
用户拖动/缩放地图（前端只渲染）
      → 云端工作台后端（同源 API、缓存、契约转换）
            → 本地天气网关（本机真实 IP 出网抓取）
                  → MSN / 微软瓦片与天气数据
```

本地网关新增天气采集程序，纯 Python 标准库实现：

| 项 | 规格 |
|---|---|
| 四个 action | `ping / json / tile / fetch_meta` |
| 主机白名单 | 非白名单主机一律拒绝 |
| 缓存策略 | 天气 JSON 600 秒、底图 7 天、气象瓦片 30 天；断网时缓存数据仍可返回 |
| 瓦片 | Bing quadkey 转换已实现，二进制瓦片 base64 回传 |
| 前端安全 | 上游 key 与精确参数仅存于网关侧，前端永远拿不到 |

**页面建设**：主页 12 张实况卡（温度/体感/降水概率/风速罗盘/湿度/紫外线/AQI/能见度/气压/太阳弧/月相 + 10 天预报）；地图页接入可交互真地图（MapLibre + 必应中国底图）与气象图层、底部时间轴推演、滚轮缩放；按 1440/1024 两档宽度 × 昼/夜两皮肤做全站尺寸验收。

### 5.6 本会话修复的典型缺陷

| 现象 | 根因 | 修复 |
|---|---|---|
| 移动端窄屏侧栏变横条后高 184px、每个导航项被拉到 166px 高，主区被压扁 | 横条布局下子项高度约束失效 | 逐子元素排查并修正弹性约束，多档宽度（960/1024/1080）实测 |
| 爬取页面融合后出现乱码/样式错乱 | 镜像内联脚本噪声（单页 9000+ 字）污染融合逻辑 | 融合前剔除噪声脚本，按子页型模板逐页接入 |
| 背景只有口令页有、且不好看 | 背景组件未全站挂载，参数与镜像基准不一致 | 组件全站化并按镜像参数校准 |
| 天气镜像页"页面少了很多" | 月度日历网格、趋势年月选择器等节点存在但未水合 | 补齐水合流程，逐节点对照镜像恢复 |

## 七、V0.4.5 · 天气系统改版与数据整合

### 7.1 改版前真实结构

- 天气页 = 页头卡 + 7 个一级横排 Tab，每个 Tab 用 **iframe 加载一张 MSN 镜像页**；
- 天气页内部没有二级导航；镜像页渲染失败处由手写 SVG 折线兜底，又丑又与数据不同步；
- 地图叠加层是抓取的静态切片而非实时帧，与官方不一致。

### 7.2 目标结构（对标官方）

| 区域 | 设计 |
|---|---|
| 左侧二级导航 | 「当前 / 每小时预报 / 详细信息 / 地图 / 月度 / 趋势」，置于工作台侧栏下方空余区、与主导航隔开，**仅在天气页显示**，支持上下滑动定位 |
| 实况可变区横栏 | 九维切换：概览、降水、风速、湿度、云量、气压、紫外线、可见度、体感温度（图标/列表两种形态） |
| 当前天气卡 | 缩小占比，降水/气温/风速以小长方形卡与当前天气同区排布 |
| 每小时预报 | 可点击切换九个维度，数据与交互齐备 |
| 下方固定区 | 详细信息卡、天气地图、月度天气、趋势历史在同一上下页面内按导航滚动定位 |
| 地图 | 保持本站内交互（不跳官方新页），可拖动、可切换图层模式 |

### 7.3 401 事故与修复

| 现象 | 根因 | 修复 |
|---|---|---|
| 上线后月度、趋势模块画不出来（401） | 天气子模块运行在 iframe 内，**iframe 里没有工作台的 `gate.js`**，请求不附访问口令、也不进入解锁排队；模块自身又不重试 | 在三个子模块（月度/逐小时/地图）侧自行实现带口令的请求与重试，部署后线上全绿（趋势、月度、环形图、气候表均 `source=live`） |

## 八、V0.4.6 · 回滚事故（教训记录）

### 8.1 事故经过

记账系统分页需求被**凭关键词错误推定**为统一账户（落锦统一账户站点）改造，AI 在本地下载了统一账户的页面与计费/鉴权脚本进行分析，用户发现后立即要求只做回滚。

### 8.2 核查结论

| 核查项 | 结论 |
|---|---|
| 生产统一账户三个关键文件（首页、计费脚本、统一鉴权脚本） | md5 与下载时逐字节一致，时间戳仍停留在 9 月 14 日 |
| 后端 | 零改动 |
| 实际动作 | 全程仅只读下载与本地新建，**从未上传或修改任何线上文件** |
| 处置 | 清理本地临时文件，不追加任何新功能 |

### 8.3 沉淀的操作纪律

- 涉及生产系统的改造，动手前必须让用户**指认具体页面/路径**，禁止仅凭关键词跨项目推定；
- 只读侦察与写操作严格分离，任何上传前先备份并展示目标路径；
- 该纪律在 V0.5 融合会话中被立即复用（先列候选路径再动手）。

## 九、V0.4.7 · 记账卡片分页与入场动效

事故澄清后，在正确的目标（工作台 `ledger` 模块：`ledger.js` / `ledger-charts.js` / `ledger-table.js`）上落地：

- 全站最后一个"无限长页"改为**卡片分组 Tab 分页**；

## 十一、版本边界

- 天气上游为 MSN/微软的公开接口与瓦片，按个人自用场景建设，密钥仅存本地网关；
- 情报分析历史存储于浏览器本地，不与云端账号体系挂钩；
- 记账数据来自账单导出文件与手工/Agent 录入，不触碰统一账户与支付接口；
- 天气真地图的流畅度受本地网关在线状态与上游响应影响，云端缓存保证断网短时可用。
