## 一、版本定位

个人工作台的**起点版本**。需求只有一条主线：把"今天上什么课"从教务群通知/纸质课表里解放出来，做成一个打开网页就能看、手机上能划的当日课程页。它验证了"把分散的学习信息聚合到一个网页"这一产品方向，后续学习通、教务、记账、天气、情报分析、AI 助手全部在这个方向上叠加。

## 二、需求还原（依据会话元数据转写）

该会话在 WorkBuddy 中仅存标题元数据，将其专业化转写后，最初的产品定义为：**一个按本机日期自动定位当日课表、以卡片呈现课程时间与教室、并支持触控左右滑动按天浏览的移动端网页**。

拆解为四条可验收需求：

| # | 需求 | 实现要点（推断） |
|---|---|---|
| 1 | 自动定位当天 | 浏览器本地时间 → 计算星期/日期，无需用户选择 |
| 2 | 当日课程卡片 | 课程名、上课时间、上课地点三要素 |
| 3 | 按天浏览 | 左右滑动/切换查看前一天、后一天 |
| 4 | 移动端可用 | 触控滑动手势，手机浏览器直接打开 |

## 三、形态与技术栈

| 维度 | V0.1 形态 |
|---|---|
| 形态 | 单页静态网页（HTML + CSS + 原生 JavaScript） |
| 后端 | 无 |
| 数据来源 | 手工录入/硬编码的课程表 |
| 构建工具 | 无，浏览器直开 |
| 部署 | 本地文件或任意静态托管 |

## 四、为后续版本留下的东西

虽然简陋，V0.1 确立了三条被后续所有版本继承的设计基因：

1. **以"天"为组织单位的信息视图**——后来的课程表、待办、天气、总览均围绕当日展开；
2. **移动优先的交互取向**——左右划动看日期的触控习惯，延续为后续各模块的卡片横滑与 Tab 手势；
3. **单页聚合的产品形态**——不做多应用跳转，所有功能长在一个页面里。

## 五、版本边界

- 无持久化、无同步，课表变动需手工改代码；
- 不含任何外部系统对接（学习通/教务/AI 均未出现）；
- 无访问控制、无服务进程；
- **原始源码与对话正文均已缺失**：WorkBuddy 数据库中该会话仅有标题与时间戳，无 `.jsonl` 事件流，故本版只记录可证实的需求与定位，不虚构实现细节。

## 六、下一版预告

V0.2 起，课程表的数据来源从"手工录入"升级为**学习通/正方教务双系统真实抓取**，网页从静态原型演进为部署在自有云服务器上、带 AI 操作智能体的完整服务。
